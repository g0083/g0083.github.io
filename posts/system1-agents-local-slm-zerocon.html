【考察】「System 1 agents」のテキスト非生成・1パス選択と、18.7 MiB極小IME（ZeroConvert-IME）が辿り着いたローカルAI信頼性の共通解

投稿日: 2026年11月22日 筆者: O-ya tech (g0083) 関連: ZeroConvert-IME / System 1 agents / SPILLWAY
Related Project / 関連プロジェクト ZeroConvert-IME
18.7 MiB極小モデル「Nano v4.1」と共有変換エンジンによるオンデバイス日本語IME（Windows / Android）
トップで見る ↗ GitHub

2026年11月下旬のAI・開発コミュニティを見ていると、ローカルAIとエージェント設計の「前提」が一段と現実的なフェーズへ移ってきたことがわかる。

11月21日には、Together AIにおいて開発用公開リポジトリ（xorl）へAIコーディングエージェントが認証情報を誤コミットしたことに端を発し、プライベートリポジトリに保存されていた過去リクエストのプロンプトサンプルが第三者にダウンロードされた事案が公表された。機密テキストや日常の打鍵データを外部推論APIに預けるリスクが改めて露呈した形だ。

その一方で、ローカルの小型モデル（SLM）を手元で動かそうとすると別の壁にぶつかる。自己回帰でテキストやJSONを自由生成させると、構文エラーや勝手な値の捏造（ハルシネーション）がどうしても紛れ込むのである。

このジレンマに対して極めて明快な解法を提示し、Hugging Face Daily Papersでも注目を集めているのが、Eleftherios Tzanis氏とMichail E. Klontzas氏による論文およびOSSフレームワーク「System 1 agents: a method for local, reliable and fast agentic AI」（SystemOneAgents）である。読んでみると、筆者が ZeroConvert-IME（18.7 MiBの極小モデル ZeroCon Model Nano v4.1）の開発で辿り着いた設計と驚くほど同じ急所を突いていた。

1. 「テキストを生成しない」System 1 agents の発想

従来のLLMエージェントは、医療・臨床データ解析のような機微領域であっても「ツール呼び出し用のJSON文字列を1トークンずつ自己回帰生成する」のが当たり前だった。しかし、小型のローカルLLMにこれをやらせると、スキーマ逸脱や引数値の勝手な作り変えが連鎖的な失敗を引き起こす。

System 1 agents が採ったアプローチは逆転している。「ツールを呼ぶためにテキストを生成しない（Text-Free Tool Calling）」のだ。

  • 決定論的コンパイラによる選択肢の生成： ツールのスキーマとユーザーのリクエスト文脈から、取り得る有効な操作と引数候補を決定論的なコンパイラが複数選択問題（Multiple-Choice）へ自動変換する。
  • 逃げ道の明示： 該当ツールがない場合の none of these や、引数が文中に存在しない場合の not specified も選択肢に組み込む。
  • 1パス（Single Forward Pass）の判定モデル： 軽量なローカル判定モデルが、生成ループを回さずたった1回のフォワードパスで選択肢の確率を評価して選ぶ。
📊 System 1 agents の実測データ（157個の生物医学ツール・1,952リクエスト）

論文の評価では、18種類の標準的なローカルLLMエージェント構成（最高正答率95.2%、引数ハルシネーション率 5.5%〜19.7%）に対し、System 1 agents は正答率 97.0% を記録。さらに決定的なのが、引数における捏造・ハルシネーション発生率が 0% に抑えられた点である。生成ループを捨てたことでレイテンシと消費電力も大幅に削られた。

2. 極小モデルが「自由生成」で壊れる理由――2611.21885 との符合

小型モデルに自由度を与えすぎると壊れるという事実は、同じく11月下旬のarXiv（arXiv:2611.21885「Language Models Can Rewrite Their Own Weights」）でも別の角度から裏付けられている。

この研究では、オープンウェイトの27Bモデルがテスト時に自身の失敗を診断して重み行列を直接書き換えることで、未知テストセットの精度を+6.6ポイント向上させ、破損したコピーも80%以上まで自己修復した。しかし注目すべきはスケーリング傾向で、同じモデル系列でも 2B・4B・9Bの小型モデルは重み書き換えに失敗するか、自分自身を壊してしまった と報告されている。

ましてやエッジやモバイルで常駐する0.03B（26.7M）〜0.09B（90.5M）クラスの極小SLMに、何でも自由生成や自己判断で完結させようとすれば破綻するのは必然だ。Zennやはてなブックマーク周辺で語られている「AIにテストケースを書かせるな、ルールを書け」という開発論や、ツール呼び出し権限をセット照合で分離する防衛手法「SPILLWAY」も含め、「不変条件（ルール）は決定論的コード側で保証し、ニューラルネットの責務を極限まで狭める」潮流がはっきり見えている。

3. ZeroConvert-IME（18.7 MiB）で実践した同じ「責務分離」

実はこれとまったく同じ問題に、日本語IME ZeroConvert-IME v0.7.0 の開発でも直面していた。

18.7 MiBの ZeroCon Model Nano v4.1（6層・約26.7Mパラメータ）に、ユーザーの打鍵した数字や英単語混じりの文をそのまま自己回帰生成させると、かつては次のような「小さなモデル特有の破綻」が避けられなかった。

  • １０きろはしる → １0キロ走る（全角・半角が1文字目と2文字目でねじれる）
  • １００えんのあめ → 1000円の飴（コーパス頻度の引力に負けて桁を捏造する）

そこで私たちが採った解は、先日の WSP論文の考察記事 でも触れた「数値と英単語保護を決定論的パイプラインへ追い出す」設計と、ランタイム側の「シングルパス評価」だった。

ZeroConvert-IMEでは、ベンチマーク専用だった nam マスクをWindows（Swift / Rust）とAndroid（JNI C++ / Kotlin）の共有変換エンジンへ組み込み、タイポ補正・ライブ変換・先読みアシストのすべてで同じ決定論的保護を通している。 

// 決定論的境界で数値・英単語を守り、極小SLMは文脈と助数詞だけに集中させる
1. 入力: "１００えんのあめ" / "SELECT name FROM users"
2. 決定論的前処理 (mask_digits_with_nam):
   → モデルには "namえんのあめ" を渡す (digits = ["100"])
3. 極小SLM推論 (18.7 MiB Nano v4.1 / llama.cpp GPT-2パッチ + KVキャッシュ再利用):
   → モデルは桁数や全半角を悩まず "nam円の飴" だけを返す
   → 複数候補が不要な経路は生ロジット1パスargmaxで即決
4. 決定論的2パス復元 (restore_nam_digits):
   → 英単語(name, dynamic, naming)をスキップしつつ "100円の飴" を確実に復元

この責務分離に加えて、推論高速化記事 でまとめた通り、ZenzCandidateEvaluator で候補リスト全体が不要な経路を「生ロジット1パスargmax」へ切り替えたこと、そして548問のタイポ補正評価で正常入力コントロール156問への誤補正ゼロを達成できたことも、「モデルに余計な生成をさせない」思想の延長線上にある。

4. 個人開発者がこれからローカルAIを設計するための3原則

System 1 agentsの成果とZeroConvert-IMEの運用経験、そして昨今のクラウド側の情報漏洩インシデントを重ね合わせると、個人開発やエッジ環境でローカルAIを組み込む際の指針は次の3点に集約される。

① 「自由生成」は最後の手段にする

ツール呼び出し、パラメータ抽出、数値・IDの保持といった「正解の集合が閉じているタスク」を小型モデルの自己回帰生成に丸投げしない。決定論的パーサやコンパイラで候補を有限集合へ落とし、モデルにはスコアリングや選択（できれば1パス）だけをさせる。

② 不変条件はモデルの「外側」のコードで握る

プロンプトやLoRAの微調整で「数字を勝手に増やすな」「英単語を壊すな」「許可されていない宛先に送るな」とお願いし続けるより、前処理・後処理・セット照合の十数行のコードを外側に置く方が、100%の保証をゼロ遅延で得られる。

③ 機微な入力ほど「ローカル完結＋最小権限」へ寄せる

日々のキー入力、ローカルファイル、社外秘のテキストを外部サーバーへ送る構成は、どれだけAPIプロバイダが安全を謳っても設定ミスやサプライチェーン経由の漏洩リスクをゼロにできない。18.7 MiBのオンデバイスSLMやブラウザWASMのように、そもそもデータが端末の外に出ないアーキテクチャを選べる領域はローカルに閉じ込めるべきだ。

おわりに

「System 1 agents」が示した“テキストを生成せずに1パスでローカルAIを確実に動かす”というアプローチは、巨大なフロンティアモデルの性能競争とは別軸にある、ソフトウェア工学としてのAI設計の王道だ。

18.7 MiBのモデルでも、決定論的コードとの境界を正しく引けば740問評価で97.16%・数値復元100%・コールド中央値20.96 msで実用に耐える。これからエージェントや組込みAIを作る際は、「どうやってモデルの自由度を下げるか」「どうやって1パスで決め切れる構造にコンパイルするか」を設計の出発点に置くと、ローカルSLMの信頼性は劇的に跳ね上がるはずだ。
