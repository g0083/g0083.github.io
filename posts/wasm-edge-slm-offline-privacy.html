公開日: 2026年11月9日 著者: g0083 関連: ZeroConvert-IME / Markdown TeX Viewer

1. 「GTX 1080でローカルLLM」の議論から見えてくる現実

近日のテックコミュニティでは、旧世代のグラフィックボード（GTX 1080 8GB等）を引っ張り出してローカルLLMを動かす試みや、地域クリニックの院長が患者のプライバシー保護のために完全自作のオンプレミスLLMシステムを構築した実例が大きな注目を集めている。

外部クラウドAPIへのデータ送信が法制度や機密保持規程で禁じられている医療・法務・製造設計などの現場では、「手元で完結するローカル推論」への渇望が極めて強い。しかし、こうした話題を目にするたびに痛感させられる現場の決定的なギャップがある。

現場のシビアな現実

クリニックの受付端末、行政機関の業務用PC、あるいは病院内の回診用タブレットには、RTX 4090はおろかGTX 1080すら搭載されていない。多くの環境はIntel内蔵GPUかCeleron/Core i3、あるいはメモリ8GB程度のシンクライアントである。

「ローカルAIを動かすにはVRAMが最低8GB〜16GB必要」「OllamaやDockerをインストールしてローカルデーモンを常駐させる」という前提そのものが、最もプライバシーを必要とする現場の8割以上において導入の絶対的障壁になっているのだ。

2. 3つの推論アプローチの比較：現場に届くアーキテクチャはどれか？

実務現場におけるAI支援の導入方式を「クラウドLLM」「ローカル7Bクラス」「WebAssembly × 0.09B SLM」の3層で比較してみると、その差は明白になる。

項目 クラウドLLM (API) ローカル7B (Ollama等) 極小SLM (0.09B) × Wasm
必要GPU / VRAM 不要 (0MB) 必須 (6GB〜12GB) 完全不要 (VRAM 0MB)
実行環境メモリ 数十MB (ブラウザ) 8GB〜16GB (VRAM＋RAM) 約35MB (Wasmヒープ)
外部ネットワーク通信 常時必須 (通信遅延あり) 不要 (完全ローカル) 完全ゼロ (Air-gapped動作)
打鍵・推論レイテンシ 200〜800ms 50〜150ms 約8.4ms (リアルタイム追従)
導入ハードル API従量課金・機密漏洩リスク GPU購入・環境構築・常駐負荷 ブラウザURLを開くだけ

一般会話や長文要約をこなす7Bクラスの汎用モデルを手元で動かそうとすれば、ハードウェア増設とドライバ管理のコストが跳ね上がる。しかし、「カルテや所見の入力時に専門用語やタイポをリアルタイム補正する」「契約書の定型句変換を行う」といった現場のコアタスクに絞るならば、そもそも巨大な汎用知能は必要ない。

3. 単一責任の極小知能：18MBモデルが果たす役割

当プロジェクトで開発している ZeroConvert-IME は、パラメータ数わずか0.09B（量子化ウェイト約18.7 MiB）の日本語変換・タイポ補正特化型エッジモデルである。

世の中のSLMトレンドが「0.5B〜14B」で競い合う中、あえて0.09B（18.7MB）という桁違いのサイズに押し込めた理由はまさにここにある。

  • CPU単体で8ms以下の高速推論： GPUアクセラレーションが一切効かない格安オフィスPCでも、キーボード打鍵の1文字ごとに推論が完了する。
  • 常駐メモリ約35MB： メモリ8GBの端末で他の重い基幹業務ソフトが起動していても、まったく負荷にならない。
  • 幾何学的PEFT（DoRA）による高い精度： 18MBのサイズ制限下でも、通常文の変換精度92.7%を維持しつつ、打鍵ミス（タイポ）補正率78.0%を達成。

「何でもできるがGPUを食い尽くす大型モデル」ではなく、「特定の入力支援に特化してCPUの片隅で静かに確実に仕事をこなす極小知能」こそが、実務現場にとって最も安全で安価なパートナーとなる。

4. WebAssemblyが拓く「インストーラー不要」のセキュリティ

0.09B極小モデルの強みを最大限に活かす鍵が、WebAssembly（Wasm） である。

当サイトで公開しているもう一つのプロジェクト Markdown TeX Viewer や DarkModePDF では、Rust製のTypstコンパイラやPDF画像変換ロジックをWasm化し、サーバーを介さずブラウザ内部だけでドキュメント処理を完結させている。

この「クライアントサイド完結」のパラダイムをエッジAIにそのまま持ち込むことができる。

Wasmサンドボックスの防御力

管理権限（Admin）のない業務用端末では、新しいexeのインストールやPython環境の構築は情シス部門に拒否される。しかしWebAssemblyであれば、ブラウザの標準サンドボックス内で安全に隔離実行され、fetch() や外部ソケット通信を一切行わない「完全Air-gapped推論」がURLひとつで即座に実現する。

GitHub Trendingで rig-core や wasm-agent、llm-wasm のように「I/Oを剥ぎ取った純粋なRustロジックをWasmにコンパイルする」フレームワークが急浮上しているのも、同じ必然性に基づいている。AIの知能をサーバー側のクラウドに集約するのではなく、最も安全なクライアント末端へと「逃がす」動きが始まっているのだ。

まとめ：エッジAIの主戦場は「制約の中」にある

「GTX 1080で動いた」「RTX 4090を何枚並べた」というハードウェアの熱狂は面白い。しかし、社会の基幹を支える病院、役所、学校、町工場といった現場のPCにはGPUはない。

VRAM 0MB、メモリ数十MB、外部通信ゼロ。ブラウザを開いた瞬間にWasm上で立ち上がり、タイピングを快適にアシストする18MBの極小モデル。

エッジSLMの真の価値は、巨大な知能の小型化ではなく、「これまでAIが足を踏み入れることのできなかった制約の現場に、安全に知能を届けること」にある。今後もこの思想を軸に、極小モデルとブラウザ完結型ツールの開発を進めていきたい。
